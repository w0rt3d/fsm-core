# Context (`Context`, `ContextManager`)

## Для чего нужен

`Context` — «сквозные» данные об операции: кто её инициировал и в рамках
какого запроса/транзакции, — которые библиотека прокидывает через
`EventBus.emit(..., context=ctx)` в каждое событие, а `EventDispatcher`
дальше передаёт в каждый вызов хука `BasePlugin`. Идея: плагин может
принимать решения не только на основании *что* изменилось (аргументы
хука вроде `node`, `pipeline`), но и *кто*/*в рамках чего* это изменение
произошло — не разбирая это из данных события вручную.

## Поля

```python
class Context(BaseModel):
    session_id: str = Field(default_factory=lambda: str(uuid.uuid4()))
    user_id: Optional[str] = None
    transaction_id: Optional[str] = None
    source: Optional[str] = None
    timestamp: datetime = Field(default_factory=datetime.now)
    metadata: Dict[str, Any] = Field(default_factory=dict)
```

- **`session_id`** — генерируется автоматически (`uuid4`), если не
  передан явно. Единственное поле, для которого библиотека сама
  гарантирует непустое значение по умолчанию.
- **`user_id`** — `Optional[str]`, не проверяется и не используется нигде
  внутри `fsm_core` — чистый транспорт для потребителя библиотеки.
- **`transaction_id`** — аналогично, свободное поле, семантику которого
  определяет вызывающий код (например, id бизнес-транзакции, в рамках
  которой сделано несколько изменений графа).
- **`source`** — аналогично `Event.source` в `event.py`, но это два
  разных поля разных классов: `Context.source` — то, что явно передаёт
  вызывающий код при создании `Context`; `Event.source` — поле dataclass
  `Event`, которое `EventBus` не заполняет никогда (см. `events.md`). Не
  путайте их.
- **`timestamp`** — момент создания объекта `Context`, не момент, когда он
  был передан в конкретное событие (если один и тот же `Context`
  переиспользуется для нескольких операций подряд — `timestamp` у всех
  этих событий будет одинаковым: временем создания контекста, а не
  временем каждой отдельной операции).
- **`metadata`** — свободный словарь для всего остального. Изначально в
  коде не имел значения по умолчанию (баг, см. `CHANGELOG.md`) — сейчас
  по умолчанию `{}`.

## Как контекст передаётся

Два пути:

1. **Явно**, аргументом в методы `GraphEngine`, которые его принимают
   (`execute`, `mutate`, `notify_changed`, `validate` — нет, `validate`
   контекст не принимает и не эмитит его в `pipeline_validated`/
   `cycle_detected`, это стоит иметь в виду: не все события несут
   контекст, даже если `Context` в принципе установлен).
2. **Неявно**, через `ContextManager.get_current()`, если аргумент
   `context` не передан вызывающим кодом:

```python
def execute(self, pipeline, context=None):
    ctx = context or self._context_manager.get_current()
    ...
```

### `ContextManager`

```python
class ContextManager:
    def __init__(self):
        self._current_context: Optional[Context] = None

    def create(self, **kwargs) -> Context:
        self._current_context = Context(**kwargs)
        return self._current_context

    def get_current(self) -> Optional[Context]: ...
    def set_current(self, context: Context) -> None: ...
    def clear(self) -> None: ...
    def has_current(self) -> bool: ...
```

`ContextManager` хранит **единственный** «текущий» контекст как обычный
атрибут экземпляра — не `threading.local()`, не `contextvars.ContextVar`.
`GraphEngine` создаёт один `ContextManager` на инстанс
(`self._context_manager = ContextManager()` в `__init__`). Если у вас один
`GraphEngine`, используемый из нескольких потоков или конкурентных
asyncio-задач одновременно, `set_current`/`get_current` — это **общая
изменяемая ячейка**, не изолированная по потоку/задаче: один поток может
увидеть контекст, установленный другим. См. также
[design_decisions.md](design_decisions.md#контекст-как-простая-переменная-не-contextvar).

## Какие поля не следует туда класть

`Context` — pydantic-модель без ограничений на типы значений в `metadata`
(`Dict[str, Any]`), и ничто в коде не запрещает положить туда что угодно.
Тем не менее, исходя из назначения класса (лёгкий, прокидываемый в каждое
событие и каждый вызов хука объект):

- **Крупные/тяжёлые объекты.** `Context` копируется по ссылке в каждое
  событие каждой операции в рамках вызова — не в сериализованном виде, но
  если внутри `metadata` лежит что-то дорогое для многократного чтения
  (например, весь снапшот графа), каждый хук, который в него заглянет,
  платит за это.
- **Секреты/учётные данные.** `Context` доходит до *любого*
  зарегистрированного плагина без исключения (пока плагин не в карантине
  и не выключен) — если у вас нет доверия ко всем плагинам в системе
  одновременно, не кладите туда что-то, что не должно быть видно всем им.
- **Состояние графа.** `Context` не предназначен для хранения ссылок на
  узлы/пайплайны как альтернативы `node`/`pipeline`, уже передаваемым
  явными аргументами хуков — это дублирование одного и того же через два
  канала.

Библиотека не проверяет и не ограничивает содержимое `metadata`
программно — все перечисленные пункты являются рекомендацией по
использованию, выведенной из архитектуры, а не механизмом, который
что-либо запрещает технически.
